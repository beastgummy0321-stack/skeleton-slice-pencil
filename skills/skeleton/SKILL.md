# /skeleton 初始化（跑完＝拿到全站可點原型）

每專案跑一次。產物常駐 repo；本 skill 跑完即退場。
中斷續跑：開場先讀 BOARD.md，有 `[skeleton>]` 行即報站續跑，已完成的站不重跑。

## 0. 溝通契約（對使用者的每一句話都適用）

1. 一次一題；AskUserQuestion，2–4 選項＋每項一句白話＋標「(推薦)」。
2. 每題附「不知道」出口：選它＝採推薦值＋記入「可反悔清單」，原型階段免費改。
3. 題域白名單：給誰用／主要做什麼／要哪些功能／長什麼樣／資料給誰看／只有使用者能做的事（帳號、金鑰）。白名單外（技術棧、目錄、同步異步、錯誤處理）一律 agent 自答自記決策，禁問使用者。
4. 問題四格路由（每題必過）：(1)事實題（code／文件查得到）→ agent 自查，禁問；
   (2)決策題且使用者答得出 → 問一題；(3)使用者不確定（「不知道」「你覺得呢」「都可以」
   或同題兩輪未收斂）→ 探路：agent 讀 code／查同類產品後，改出 2–4 選項＋每項取捨一句
   ＋標推薦再問，禁追問第三次；(4)探路後仍答不出 → /to-questionnaire 生問卷，
   或採推薦＋記可反悔清單。
5. 禁術語；非用不可附一句比喻。時間講具體（「約一杯咖啡的時間」）。
6. 報位置：「第 N 站，共 M 站」。不可逆先講後果再問。出錯只說「發生什麼＋我怎麼修」，不貼 log。
7. 本檔其餘部分是內部作業指令，照術語走，不外洩給使用者。

## 1. 判定新舊

repo 有既有原始碼（package.json 或 src 非空）→ 走第 5 節「舊專案」；否則走第 2 節。

## 2. 新專案站一：訪談樹（把使用者當三歲小孩，手把手挖）

引擎照 /grilling（設計樹＋frontier＋事實 agent 自查），互動形式被第 0 節覆蓋：
一輪只問一題，禁整個 frontier 一次拋出、禁 Q1–Qn 文字牆。

樹的層次（依答案展開，每層一次一題）：

1. 這個程式給誰用？
2. 打開它最常做的一件事是什麼？
3. agent 查同類產品出功能草案（禁憑記憶，查現行產品），逐項問「同類程式通常有 X，要嗎？」要／不要／不知道(推薦)。
4. 資料給誰看？（只有自己／要分享／要多人）
5. 只有使用者本人能做的事（申請帳號、API 金鑰、金流）→ 用 /wizard 生成互動引導精靈帶他做。

業務細節題（假資料階段不影響答案者）記入 UNKNOWN 清單推遲到 /slice。
使用者自己也答不出的題 → /to-questionnaire 生成問卷讓他拿去問懂的人。
凍結線（防規劃無限延長）：訪談只凍兩類——code-rules「不可逆決定」表命中項、
使用者看得到的行為。線外細節（可逆、單模組內部、換個做法只改一處）禁問禁凍，
帶進實作由 agent 自決＋標 `ponytail:` 註解或記可反悔清單。
線外議題討論兩輪即記可反悔、開工，禁第三輪。
樹走空 → 一頁白話摘要（功能清單＋每功能一句）→ 使用者點頭＝功能地圖定案。

## 3. 新專案站二：地基（靜默建置）

stack：Next.js+TS+Tailwind+shadcn/ui+tRPC+zod+Drizzle+SQLite 起步（後換 Postgres）
＋dependency-cruiser＋husky pre-commit＋Playwright。

1. 逐項查證現行版本與維護狀態（context7／官方 changelog，禁憑記憶）。
   結果列表：名稱｜版本｜最後更新｜授權。
2. 安裝清單＋磁碟影響 → 使用者點頭才執行。未點頭不得裝任何東西。
3. 模組軌道照 本 plugin 的 `rules/container-contract.md`（本 SKILL.md 上兩層的 rules 目錄）（含第八節好找優先）：
   `src/modules/<畫面名>/index.ts` 唯一進入點；depcruise 規則＝跨模組僅准 import 進入點＋禁循環依賴。
4. 證紅：故意寫一條跨界 import → depcruise 必須報錯 → 移除。不紅＝規則沒生效，修到會紅為止。
5. Playwright 冒煙 1 條（首頁載入），同樣證紅（弄壞→紅→改回）。

## 4. 新專案站三：全站可點原型

1. 風格錨：功能地圖第一個畫面生 3 版靜態（ui-ux-pro-max 出方向 → design-taste-frontend 生成）
   → 瀏覽器 preview 挑 1 版＝全站 design token 定案。此頁兼 tracer：畫面→tRPC→DB 一張表打通。
2. 畫面契約：每畫面產 `src/schemas/<畫面名>.ts`（zod schema＋action 簽名；註解＝資料哪裡來）。
   外部平台欄位用 /research 查官方文件填入＋註出處；查無 → 記 UNKNOWN，禁自創。
3. 平行生成：每畫面一個 subagent；派工 prompt 附風格錨 token＋共用 mocks 入口
   ＋本 plugin 的 `rules/container-contract.md`（本 SKILL.md 上兩層的 rules 目錄） 原文（不摘要、不重寫）。禁自選色、禁自加依賴。
4. 假資料活在 `src/mocks/` 單一入口；四態（正常／空／失敗／進行中）做成可切換開關；
   假資料必須醜（長字串、0、負數、大量筆數、壞圖各 ≥1）。`if (mock)` 分支一律禁止。
5. 交付：頁能互跳、四態可切 → 使用者玩過點頭。
   BOARD.md 一次寫滿 N 行 `[ ]`（每畫面一行，待 /slice 換真線）。

原型階段加刪功能免費：加＝同風格錨生成該頁＋看板加行；刪＝刪頁＋刪看板行＋刪畫面契約。
只動受影響頁，已生成頁不重生、風格不重問。換真線後的加刪走 /slice。
每站過關當下更新 BOARD.md `[skeleton>]` 行，不得累積到收工才寫。

## 5. 舊專案：只加不改

- 改動任何既有原始碼與結構一律禁止。違反＝本 skill 失敗。
- 現有產品即原型，不再生成。反向蒸餾：每既有畫面從 code 反推畫面契約落 `src/schemas/`，
  標注「現況蒸餾，未凍結」——是描述不是規範。
- depcruise 掛基線模式：既有違規記入 baseline 檔，只擋新增的違規。
- 加：`src/schemas/`、BOARD.md、專案 CLAUDE.md、pre-commit（僅 lint 新改檔）。
- 盤點：派唯讀 subagent 掃模組結構（Grep 定位，禁整檔讀）→
  每模組一行：名字｜糾纏度（綠／黃／紅）｜危險區（金流／外部 API／共用狀態）。
  只落 BOARD.md `[ ]` 行（照建議遷移順序排）＋專案 CLAUDE.md 地標節，不另開地圖文件。
- 使用者要的新畫面才走第 4 節生成；風格錨從既有 UI 蒸餾，禁用預設主題。
- 既有模組不補登記；碰到才照 /slice C-舊 規則逐片遷。

## 6. 常駐三件套

1. `BOARD.md`（repo 根）：

   ```
   # 切片看板（只放未開始＋進行中；完成即刪行，歷史＝git log）
   - [>] <編號> <名字> ｜ 目前站 ｜ 卡點一句話
   - [ ] <編號> <名字>
   ```

2. 專案 `CLAUDE.md`：抄 `assets/project-claude-template.md` 填空後寫入。
   專案已有 CLAUDE.md → 停下問使用者怎麼併，不得覆蓋。
3. 開場廣播由專案 CLAUDE.md 第一節承擔（開 session 先讀 BOARD.md、有 [>] 主動報站）。

## 7. 收工檢核（全過才報完工）

原型可點且四態可切｜depcruise 證過紅｜冒煙證過紅｜BOARD.md 寫滿｜專案 CLAUDE.md 在｜
安裝清單經點頭｜可反悔清單＋UNKNOWN 清單已交付。
回報格式：三件套路徑＋證紅紀錄＋跳過了什麼。
