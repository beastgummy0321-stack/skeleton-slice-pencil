# skeleton-slice rules (injected every session)

Injected below: workflow.md, reuse-first.md. Loaded on demand by /skeleton, /slice, /container-contract: container-contract.md, screen-contract.md. Pasted verbatim into every dispatch prompt, because a subagent has no SessionStart and therefore never sees this file: agent-brief.md.

- A new check must be proven red once (break the behaviour, see it fail, restore) before it counts.
- "X does not exist" requires having searched everywhere X could be.
- Subagents read files by line range or Grep hit, never whole files. Line count never orders a split — a split is a module-boundary decision, and the module's own total already lands in every completion report.
- **Precedence, so that two agents given the same conflict reach the same answer: `CONSTITUTION.md` > ADR > `docs/contracts/<module>.md` > the ticket.** A ticket that contradicts anything above it is neither implemented nor silently corrected — it is reported as `blocked-upstream` before any code is written. Measured: handed the same conflict (a ticket specifying a table with no `org_id`, against a constitution requiring one on every table), two agents on the same model reached opposite conclusions and both shipped, each with a confident written justification — one deciding the ticket exempts the constitution, the other deciding the constitution overrides the ticket. Neither escalated. An unwritten precedence is not a default; it is a coin flip that reads like a ruling.
- **A blank is not a licence, and a wall is not a detour.** A hard-to-reverse decision (undoing it would redo finished work) that the constitution, a contract or the ticket has not settled is escalated — open an issue or ask — never filled in by the agent. When reality blocks the plan, stop and report; reinterpreting the goal to get around the wall is the same offence as filling the blank. Routing around a shared constraint is that offence in its commonest disguise: bypassing a shared function instead of editing it, post-processing its output, duplicating it under a new name, or narrowing what a test asserts. Measured: told to add a field that a shared allow-list filtered out, and that the ticket said touched no shared file, an implementer left the shared file alone and mutated its return value afterwards — every gate stayed green, the completion report read as principled, and the allow-list quietly stopped being one. Reversible single-module details stay the agent's to decide. A number **or a literal recipe** stated without a named source is a filled blank, and **the ticket writer is bound by this exactly as the implementer is** — a ticket is not a safe place to put something remembered rather than checked, because the implementer will follow it word for word and the gates will agree. Measured: a ticket dictated the `SET search_path` clause of a `SECURITY DEFINER` function from memory and omitted `pg_temp`; the implementer followed it exactly, eight machine gates and 710 tests went green, and the result was a live privilege escalation — any logged-in user could shadow the ownership table with a temp table and read another tenant's credentials.
- Project docs are one tree: `CONSTITUTION.md` (≤20 lines, the only entry), `BOARD.md` (points to it), and `docs/` — `CONTEXT.md`, `adr/`, `contracts/<module>.md`, `issues/<slug>/` (gitignored; a ticket dies with its board row and is deleted freely). A doc unreachable from `CONSTITUTION.md` in ≤2 links is retired: unlink it, or gitignore + `git rm -r --cached` — that needs no permission; deleting a tracked file needs the user's.
- **Only the loaded surface is budgeted — a file nobody reads costs nothing.** Three tiers: always-loaded rule files (held by `load-budget`, 500 lines); the dispatch surface (`CONSTITUTION.md` + one `decision:` line per ADR + the contract pages the ticket names); and the bodies, which carry **no size limit at all**. Never cap, ratchet or trim docs by their total line count: a shared quota makes writing one doc cost another, and the doc that gets cut is whichever one is not being defended today.
- Every ADR opens with `id` / `decision` (the ruling itself, one imperative sentence, ≤120 chars) / `applies-to` (the paths it governs) / `supersedes` (the ids it replaces, or `none` — asked every time, because the answer is what retires the old ruling) / `status` (`in-force` or `superseded-by: NNNN`). Retirement is a link with two ends: claiming to supersede an ADR without setting that ADR's `status`, or the reverse, is a red gate. There is no index file to drift: `node "{{PLUGIN_ROOT}}/hooks/adr-index.mjs" <path…>` computes the rows governing the paths a ticket touches, so a dispatch prompt carries the two or three ADRs that bind it and never the other twenty-eight.
- The decision record is swept before **every** agent dispatch, not only when an ADR is written — a write-time gate sees one file and misses everything that arrives another way. An ADR written by Bash, a rename that stranded an `applies-to`, a duplicated id, a file one folder deeper, a contract page citing a dead id: each blocks the dispatch it would have poisoned. Fix the record or move the ADR to `docs/adr/retired/`; never dispatch around it.
- **Deletion is two-directional.** Retiring an ADR or deleting a module is not `git mv` and `rm`: in the same commit, every document that pointed at it is fixed, or says out loud that it is gone. The frontmatter link (`supersedes` ↔ `status`) joins two ADRs and says nothing about the twenty pages that still name the old one — so the sweep enforces the third end: **an in-force page naming a retired ADR, in a paragraph that does not say it is retired, is a red gate.** Clearing it means writing the truth, never registering an exemption. Before moving anything: `grep -rn "ADR 00NN\|<the path being deleted>" --include=*.md .`
- An ADR is written by main chat when Gate A or a route C decision is settled — never by an implementer finishing a ticket, and never as a record of work done. A reversible, module-local decision is one line under `decisions in force` in `docs/contracts/<module>.md`; its reasoning stays in the ticket and dies with it.
- Finished work has exactly three exits: deliver, open an issue, or propose a constitution amendment. Writing another explanatory doc is not an exit.
- Irreversible decisions (data model, module boundary, sync/async, error & transaction boundary, and which component owns a judgment call) are settled at Gate A before coding, never deferred with "refactor later"; record them with the domain-modeling skill.
