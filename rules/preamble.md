# skeleton-slice rules (injected every session)

Injected: this file, workflow.md, reuse-first.md. Loaded on demand by /skeleton, /slice, /container-contract: container-contract.md, screen-contract.md. Pasted verbatim into every dispatch prompt, because a subagent has no SessionStart: agent-brief.md. The evidence behind each rule lives in this plugin's git log, not here.

- A new check must be proven red once (break the behaviour, see it fail, restore) before it counts.
- "X does not exist" requires having searched everywhere X could be.
- Subagents read files by line range or Grep hit, never whole files.
- Never widen a tolerance list (known-drift, known-oversized, allowed-failures, skip markers, a frozen baseline) to turn a gate red→green; narrowing what a gate applies to is a different act and needs a written decision. Never rewrite a test to assert current broken behaviour. Fix the code, or report it and stop.
- **Precedence: `CONSTITUTION.md` > ADR > `docs/contracts/<module>.md` > the ticket.** A ticket that contradicts anything above it is neither implemented nor silently corrected — it is `blocked-upstream` before any code is written. An unwritten precedence is a coin flip that reads like a ruling.
- **A blank is not a licence, and a wall is not a detour.** A hard-to-reverse decision (undoing it would redo finished work) that no document above has settled is escalated — open an issue or ask — never filled in by the agent. When reality blocks the plan, stop and report: reinterpreting the goal, bypassing a shared function instead of editing it, post-processing its output, duplicating it under a new name, or narrowing what a test asserts is the same offence. A number or a literal recipe stated without a named source is a filled blank, and the ticket writer is bound by this exactly as the implementer is. Reversible single-module details stay the agent's to decide.
- Irreversible decisions (data model, module boundary, sync/async, error & transaction boundary, which component owns a judgment call) are settled at Gate A before coding, never deferred with "refactor later"; record them with the domain-modeling skill.
- Project docs are one tree: `CONSTITUTION.md` (≤20 lines, the only entry) → `BOARD.md` + `docs/` (`CONTEXT.md`, `adr/`, `contracts/<module>.md`, `issues/<goal>/` — gitignored, one folder per board row, deleted with it). A doc unreachable from `CONSTITUTION.md` in ≤2 links is retired: unlink it, or gitignore + `git rm -r --cached` (no permission needed; deleting a tracked file needs the user's). Bodies have no length limit; only what gets loaded into a session or a dispatch prompt is worth trimming.
- Every ADR opens with `id` / `decision` (the ruling itself, one imperative sentence, ≤120 chars) / `applies-to` (the paths it governs) / `supersedes` (ids, or `none`) / `status` (`in-force` or `superseded-by: NNNN`). `node "{{PLUGIN_ROOT}}/hooks/adr-index.mjs" <path…>` prints the rows governing the given paths. The dispatch gate sweeps the whole record before every Agent call — frontmatter, duplicate ids, both ends of every supersedes link, and any in-force page naming a retired ADR in a paragraph that does not say so. Fix the record or move the ADR to `docs/adr/retired/`; never dispatch around it. Before retiring an ADR or deleting a module: `grep -rn "ADR 00NN\|<the path>" --include=*.md .` and fix every hit in the same commit.
- An ADR is written by main chat when Gate A or a route C decision is settled — never by an implementer finishing a ticket, never as a record of work done. A reversible module-local decision is one line under `decisions in force` in the contract page; its reasoning stays in the ticket and dies with it.
- Finished work has exactly three exits: deliver, open an issue, or propose a constitution amendment. Writing another explanatory doc is not an exit.
- **The board is a list of goals, not a journal.** `BOARD.md` is the title, `> ` pointer lines, and one line per goal naming its `docs/issues/<goal>/` folder — nothing else, held by `board-shape` on every write and at every dispatch. Everything below a goal lives in its folder: tickets `NN-<name>.md` (four sections, dispatched), issues `issue-<name>.md` (a defect or wish found mid-ticket that this ticket does not fix: cause, impact, `file:line`, `Status:`; it becomes a ticket by being renamed and filled). A measured fact goes to the module's contract page, a cross-module lesson to `CONTEXT.md`, a rejected option to the ADR; finished work is deleted, git log is the archive. A ticket dies when it ships; the row dies when its folder is empty.
