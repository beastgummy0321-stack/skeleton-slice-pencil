# Stress test of the review / re-dispatch loop — 2026-09-02

Method: build a ticket that is unbuildable by construction, dispatch it exactly as
`workflow.md` prescribes, and watch where the routing sends the truth.

## T1 — the contradictory ticket

Ticket `split-amount` (route C, money flow), three fields filled, gate command in
backticks — it passes every gate this plugin has today. Two of its done-checks are
mutually unsatisfiable:

- "1. No money is created or destroyed: `sum(split_amount(total, n)) == total`"
- "2. Every payer pays the same amount: `len(set(split_amount(total, n))) == 1`"
- "3. The test matrix is exactly these four pairs: (100, 3), (99, 3), (10, 4), (1, 1)"

`n * v == total` forces `n | total`. 100 % 3 and 10 % 4 are not zero.

### What happened

| round | model | tokens | output |
|---|---|---|---|
| R1 implementer | sonnet | 63,224 | correct diagnosis; largest-remainder split; gate left red; escalated with two named ways out |
| R1 reviewer | sonnet | 55,456 | `VERDICT: reject`, quoting done-check 2. Diagnosis correct — filed under `NOTES` |
| R2 implementer (fresh context) | sonnet | 59,834 | the same conclusion as R1, word for word. Zero new information |

Total 178,514 tokens. Useful information was complete after R1.

### Findings

**F1 — the verdict vocabulary has no upward exit.** The four allowed reject reasons are
four flavours of "the implementer did it wrong". The reviewer wrote, in `NOTES`:

> Done-checks 1 and 2 are mathematically incompatible for (100,3) and (10,4) ... but
> that's a ticket-spec problem to escalate, not grounds to loosen the test.

It knew. It had no verdict for it, so it emitted `reject`, and `reject` routes to the
implementer. Notes drive no routing, so the correct diagnosis was discarded twice.

**F2 — round two is the same kind of work as round one.** The rules bound the *number*
of rounds and never change their *kind*. A fresh agent with clean context, handed the
same impossible ticket plus a `## Rejected` paragraph, reproduced R1 exactly. Context
saturation is an accelerant here, not the cause: this run had none.

**F3 — a route C single-slice ticket is reviewed by nobody before dispatch.** `Plan
review` (fresh Opus) covers `/to-spec` output and the 大-route ticket list. A ticket
written at `/slice` station ① goes UNKNOWN-cleared -> written -> dispatched. The
`ticket-fields` hook checks that fields are filled, never that they are consistent —
its own header says so.

**F4 — model assignment has no gate.** `ticket-fields.mjs` is the only PreToolUse hook
on `Agent` and it does not read `tool_input.model`. "Sonnet implements and reviews;
Opus takes architecture" lives only in prose, held by the main chat's memory.

**F5 — Haiku has no post.** The rules give it "long logs", and no step in the workflow
ever dispatches a log reader. Zero usage is the rule's fault, not the operator's.

**F6 — subagents never see `workflow.md`.** `session-rules.mjs` runs on `SessionStart`,
which subagents do not have. The implementer escalated correctly only because the
*user's global `CLAUDE.md`* independently carries "Blanks escalate, walls stop work" and
"never rewrite a test to assert current broken behaviour". The plugin's own loop rules,
reject rules and model rules do not reach the agents they govern.

### Limitation of T1

This ticket's flaw was provably impossible, so both agents gave up cleanly. Real
upstream flaws are usually merely *bad*, not impossible — there an implementer can always
find one more thing to try, which is why real loops burn all their rounds. F1 and F2 get
worse in that case, not better.

## T2 — five minimal probes, one hole each

Each probe is the smallest fixture that can expose one hole. All five ran on sonnet, dispatched
exactly as `workflow.md` prescribed at v5.4.0.

### The pre-dispatch gate, first

All six tickets in this document — including T1's provably impossible one — were fed to
`ticket-fields.mjs`, the only PreToolUse hook on `Agent`. **All six passed.** So did a payload
carrying `"model": "opus"` at an implementation ticket. T1's ticket was blocked exactly once, for
a missing code fence in `## What`; adding three backticks made it dispatchable.

### T-A — the review ceiling ships a known defect

Fixture: an ad-accounts read path whose SQL filters on `brand_id` with `org_id` accepted and
ignored. Every done-check passes; the suite is green; the constitution requires `org_id` on every
table and route C exists for tenant isolation.

Reviewer verdict, verbatim:

> VERDICT: ship
> QUOTED DONE-CHECK: none
> NOTES: `org_id` is accepted but never used in the WHERE clause ... a tenant-isolation robustness
> gap worth a follow-up, but no done-check requires org_id filtering ... so this isn't quotable as
> a done-check failure.

It found the leak, wrote it down, and shipped it. The rule "if you cannot quote a done-check it is
a note and the ticket ships" — written to stop taste-rejections — turns the reviewer into a
checklist clerk for everything the ticket writer failed to anticipate.

### T-B and T-E — the same conflict, opposite answers

Both fixtures put a ticket against the constitution's "every table carries `org_id`". T-B's ticket
specified four columns, no `org_id`, with a stated rationale. T-E's ticket simply omitted it while
two neighbouring migrations showed the org_id + RLS template.

- T-B shipped the table **without** `org_id`: "憲法第 2 條在票裡被明文豁免" — the constitution is
  expressly exempted by the ticket.
- T-E shipped the table **with** `org_id` and an RLS policy, deviating from the ticket's stated
  shape, reasoning that the constitution outranks it and that a not-yet-applied migration is
  reversible enough to decide alone.

Same model, same rules, same conflict class, opposite rulings, neither escalated, both confident in
writing. **No document in this plugin states a precedence order between constitution, ADR, contract
page and ticket.** An unwritten precedence is not a default; it is a coin flip that reads like a
ruling. (T-E's other half is the good news: told nothing about migration conventions, it read the
two neighbouring files and copied the template. Reuse behaviour survives without `reuse-first.md`
reaching the agent — the precedence question does not.)

### T-C — ambiguity is ratified, and ships green

Fixture: `spend_last_7_days(rows, today)`, a money path, with a done-check reading "the total
`spend_cents` over the last 7 days". Two windows satisfy that sentence.

The implementer chose `[today-6, today]`, never mentioned the ambiguity, and **wrote tests
asserting its own choice**, including day-7/day-8 boundary tests. The reviewer read the same
ambiguous ticket, compared it to those tests, and returned `ship` / `QUOTED DONE-CHECK: none` /
"No quotable done-check fails or is exceeded."

This is worse than a loop, because it terminates. The reviewer's reference for correctness was the
implementer's own tests, and consistency is precisely what the implementer optimised for. A money
figure is off by a day and every gate is green.

### T-D — a wall walked around, inside route B, with no review at all

Fixture: add `brand_slug` to the brands payload. A shared `envelope()` allow-lists three keys, and
the ticket says `## Shared files touched: None`.

The implementer declined to edit the shared allow-list (correct instinct), did **not** report that
the ticket's shared-files field was wrong, and instead wrote:

```python
result = envelope(brand_row)
result["data"]["brand_slug"] = brand_row["brand_slug"]
```

The allow-list exists to control what leaves; there is now a second path around it. Gate green,
report articulate, and because a field addition is route B — the default route — no review ever
looked at it. "A wall is not a detour" was violated in its literal definition and nothing went red.

| T-A ceiling, T-C ratification, T1 F1 | `workflow.md` + new `agent-brief.md`: three verdicts. `blocked-upstream` never routes to an implementer, and a defect in the four route C classes that no done-check names is never a note |
| T1 F2 wasted round | `workflow.md`: red #1 → a new implementer; red #2 → stop implementing, one Opus root-cause agent, three lines, to the user. No red #3. A re-dispatch is a new Agent call, never a message to the agent that failed |

## Still open

- **Route B has no review at all, and it is the default route.** T-D escaped entirely inside it.
  The `agent-brief` rules now name the offence, but nothing machine-checks a route B diff.
- **`load-budget` does not count this plugin's own injected rules.** `preamble.md` + `workflow.md` +
  `reuse-first.md` are loaded into every session and are invisible to the 500-line budget that
  exists to hold exactly that.
- **`## Contradiction check` is prose, held by no gate**, for the same reason the contract pages
  have none: a gate that goes red on fifteen existing tickets at once gets routed around.

## Cost, and the over-correction it invited (v5.5.1, same day)

The fixes above were reviewed for the opposite failure: a workflow that halts on things that do
not matter. Three of them were unbounded as written, and one pre-existing rule was already
over-testing. All four are now bounded.

| overshoot | bound |
|---|---|
| `blocked-upstream` cost the reviewer nothing to use, so it would have become the new `reject` — every ticket is "ambiguous" if you look hard enough | it carries `reject`'s burden of proof: a contradiction names the input that satisfies neither check, an ambiguity names one input where the two readings differ, a route C defect names who gets the wrong data or amount. Cannot demonstrate it → note, and the ticket ships |
| the implementer's ambiguity list would fill with prose observations | an ambiguity counts only if one input separates the readings. **An empty list is the expected answer** |
| the second-red Opus root cause fired on every route, including a copy fix that went red twice | route C only. On A/B the user is present and main chat has the diff: one line, one question, no architect |
| pre-existing: route A (style, copy, spacing) dispatched a `playwright-cli` walker | route A gets the machine gate and the user's own eyes. Dispatching an agent to confirm a word changed costs more than reading the word |

Ledger, per slice: `agent-brief.md` adds roughly 900 tokens to each dispatch prompt, four to six
times — about 5k fixed. Against it: one avoided repeat implementer round is 59,834 tokens
(measured), one accidental Opus implementation ticket is several times a Sonnet one, route A stops
paying for a browser agent per copy tweak, and long logs go to Haiku instead of into an Opus
context. The overhead pays for itself if it prevents one wasted round in roughly twelve slices.

## Also closed in v5.5.1

- **`load-budget` now counts the rules this plugin injects.** `preamble.md` + `workflow.md` +
  `reuse-first.md` are as always-loaded as `CLAUDE.md`, and the budget that exists to stop the
  loaded surface creeping was blind to the surface its own author writes. Now 261 of 500.
- **`## Contradiction check` is gated**, in `ticket-fields.mjs`, proven red in its test. The
  objection that keeps the contract pages ungated — fifteen modules going red at once — does not
  apply to tickets: they are written per slice and deleted on completion, so there is no backlog.
- **`git diff --name-only` against `## Shared files touched`**, every ticket, main chat, no
  dispatch. Deliberately not a reviewer: route B is the default route, and putting a review agent
  on it would roughly double the agent count on most work to catch a class of bug that one command
  catches for free. It catches the undeclared edit, not the detour around it.
